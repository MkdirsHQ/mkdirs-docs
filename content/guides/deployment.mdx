The template builds a static FumaPress site and publishes the generated files directly with Cloudflare Workers Static Assets. It has no Worker entry point, runtime code, or Assets binding.

<Steps>
  <Step>
    ### Set site identity

    Update `src/site.config.ts`, `public/robots.txt`, and the Worker name in `wrangler.jsonc`.
  </Step>
  <Step>
    ### Authenticate Wrangler

    Use `wrangler login` locally or provide `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` in CI.
  </Step>
  <Step>
    ### Run the full validation

    ```bash
    pnpm check
    ```

    This runs generated source checks, TypeScript, the production build, and a Wrangler dry run.
  </Step>
  <Step>
    ### Deploy

    ```bash
    pnpm deploy
    ```
  </Step>
</Steps>

## Custom domain

Add a Worker Custom Domain when Cloudflare is authoritative for the zone:

```json
{
  "routes": [
    {
      "pattern": "docs.example.com",
      "custom_domain": true
    }
  ]
}
```

<Callout type="warn" title="Check existing DNS">
  A custom domain cannot replace a hostname that already has a conflicting CNAME record. Confirm the hostname before deploying the route.
</Callout>
